# گزارش ریفکتور معماری

این کار روی شاخهٔ `codex/architecture-refactor` و از آخرین `main` پس از ادغام PR شمارهٔ ۷ شروع شد. شاخه‌های قدیمی `second` و `codex/fix-people-validation`، پس از تأیید ادغام PRها، از لوکال و GitHub حذف شدند.

## مرزهایی که حفظ شدند

- فایل schema، تمام migrationها و نام جدول‌ها، ستون‌ها و روابط تغییر نکردند. تست، هش این فایل‌ها را با نسخهٔ قبل از ریفکتور مقایسه می‌کند.
- هیچ migration، seed یا تستی روی دیتابیس واقعی اجرا نشد. تست عملیات ثبت و ویرایش، Prisma را با mock جایگزین می‌کند.
- تمام URLهای قبلی، از جمله `plantvarities` و `recoveryRoom`، حفظ شدند. نام پوشه‌های داخلی اصلاح شده، ولی لینک‌ها و QRهای موجود معتبر می‌مانند.
- طراحی و جریان فرم‌ها، لیست‌ها، جزئیات، CSV و چاپ حفظ شده‌اند. خطاها و نمایش مقادیر صفر در موارد معیوب اصلاح شده‌اند.

## ساختار جدید

```text
app/                         مسیرها و ترکیب صفحه‌ها
features/<feature>/
  components/                فرم، جدول و نمایش همان قابلیت
  actions.ts                 ورودی عمومی عملیات سرور
  schema/                    قرارداد ثبت و ویرایش
  domain/                    قواعد مستقل، در قابلیت‌هایی که نیاز دارند
  types/                     قرارداد دادهٔ مستقل از Prisma
  server/                    query، ثبت، ویرایش و حذف
  exports/                   تبدیل داده برای CSV، بدون query جدید
server/
  auth/                      نشست و احراز هویت
  db/                        client، تراکنش و تبدیل داده
  actions/                   تبدیل خطا به نتیجهٔ قابل نمایش
shared/                      اجزای UI و ابزارهای قابل استفادهٔ مجدد
tests/                       تست رفتار و مرزهای معماری
scripts/                     بررسی معماری، خروجی build و تست اجرای نسخهٔ تولیدی
```

نام قابلیت‌ها یکدست شده: `people`، `greenhouses`، `plant-varieties`، `growth-stages`، `seed-packages`، `seed-warehousing`، `seed-planting`، `seedling-cycles`، `nursery-rooms` و `recovery-rooms`.

جهت وابستگی این است: صفحه به UI قابلیت، UI به action عمومی و قرارداد داده، action به قواعد ورودی و زیرساخت سرور. Prisma در UI وارد نمی‌شود. `shared` هم به قابلیت مشخص یا زیرساخت وابسته نیست. query عمومی QR از action خصوصی جدا شده است؛ عملیات خصوصی نشست معتبر می‌خواهند. تست معماری، نقض این مرزها و وابستگی حلقوی را رد می‌کند.

## تغییرات عملی

- اعتبارسنجی هنگام ثبت و ویرایش انجام می‌شود. خواندن اشخاص قدیمی فقط شکل داده را بررسی می‌کند؛ ایمیل ناقص یا مقدار کوتاه قدیمی، کل صفحه را متوقف نمی‌کند.
- ورودی‌های نوشتن whitelist دارند؛ ID و اشیای رابطه‌ای از payload ثبت عبور نمی‌کنند. طول متن‌ها و صحیح بودن عددهای مورد نیاز با ستون‌های فعلی هماهنگ شده است.
- نتیجهٔ خطای ثبت و حذف، موفقیت تلقی نمی‌شود. خطاهای رابطه، رکورد حذف‌شده، ورودی نامعتبر و قطع ارتباط پیام قابل فهم دارند. loading بعد از شکست آزاد می‌شود و خطای فیلد در فرم نمایش داده می‌شود.
- کد شخص در سرور و در تراکنش Serializable تولید می‌شود؛ تعارض تراکنش با تعداد تلاش محدود مدیریت می‌شود. مقدار پیشنهادی مرورگر، مبنای ثبت نیست.
- ثبت ریکاوری و تلفات کارگران در یک تراکنش انجام می‌شود. مجموع تلفات در سرور محاسبه می‌شود؛ کارگر مربوط به عملیات دیگر، تکرار کارگر و ترتیب نادرست تاریخ‌ها رد می‌شوند.
- تبدیل Decimal، تاریخ و QR باینری متمرکز شده است. صفر و `false` از بین نمی‌روند؛ از جمله در ویرایش تراکنش انبار.
- جدول، صفحه‌بندی، مودال فرم، سربرگ‌های یکسان، پیام نتیجه، تاریخ شمسی، تصویر QR، برچسب چاپ، دریافت لیست و تبدیل CSV اجزای مشترک دارند. محتوای گواهی سفارش از مدیریت مودال و چاپ جدا شده است.
- نوع‌های `any` و importهای بدون مصرف از سورس اجرایی حذف شده‌اند. اسکریپت‌های تشخیصی قدیمی به `scripts/diagnostics` منتقل و اصلاح شده‌اند؛ این اسکریپت‌ها خودکار اجرا نمی‌شوند.
- پکیج‌های بلااستفاده حذف شدند. Next.js و اصلاحات سازگار وابستگی‌ها به‌روز شدند. نسخه‌های CLI و client در Prisma 6 هم‌تراز هستند؛ نسخهٔ اصلی Prisma و schema ثابت مانده‌اند.
- seed دیگر رمز پیش‌فرض داخل سورس ندارد. اجرای دستی آن به `ADMIN_USERNAME` و `ADMIN_PASSWORD` نیاز دارد؛ در این کار اجرا نشده است.
- بستهٔ standalone، فایل‌های محیطی و آرشیوهای لوکال را حمل نمی‌کند. مسیر کپی client در Docker اصلاح شده و `npm start` خروجی واقعی standalone را اجرا می‌کند. متغیرهای محیطی تولید باید از تنظیمات استقرار تأمین شوند.

## بررسی‌ها

```bash
npx prisma generate        # فقط تولید client؛ بدون تغییر دیتابیس
npm run check              # lint، TypeScript و تست‌ها
npm run format:check
npm run build              # همراه آماده‌سازی و بررسی standalone
node scripts/smoke-build.mjs
npm audit --omit=dev
```

تست‌ها اعتبارسنجی، دسترسی خصوصی، خطاهای دیتابیس با mock، تراکنش، تلفات، مقدار صفر/false، CSV، جدول، URL و محتوای چاپ را پوشش می‌دهند. تست اجرای تولیدی با دیتابیس عمداً غیرفعال، صفحهٔ ورود، CSS، لوگو، آیکون، هدایت کاربر ناشناس و QR با ID نامعتبر را بررسی می‌کند. CI همین بررسی‌ها را اجرا می‌کند.

## محدودیت‌های بررسی

تست ثبت روی SQL Server واقعی و تست دستگاه چاپ فیزیکی انجام نشده است. تعریف سطح دسترسی نقش‌ها یا اضافه کردن آمار داشبورد، قابلیت جدید است و در این ریفکتور به منطق موجود اضافه نشده است.

audit وابستگی‌های اجرایی پس از اصلاحات صفر است. پنج گزارش وابسته به یک آسیب‌پذیری در زنجیرهٔ ابزار توسعهٔ ESLint/fast-glob/braces باقی مانده‌اند؛ npm برای آن‌ها downgrade ناسازگار ESLint پیشنهاد می‌کند. چنین downgrade‌ای اعمال نشده است. [گزارش braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).

دو هشدار tracing از سورس تولیدشدهٔ Prisma در Turbopack باقی است. سورس تولیدشده دست‌کاری نشده؛ خروجی نهایی مستقل بررسی می‌شود تا فایل محیطی یا آرشیو لوکال داخل آن نباشد. [مستندات رسمی خروجی standalone و tracing](https://nextjs.org/docs/app/api-reference/config/next-config-js/output).
